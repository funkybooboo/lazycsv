**Status:** Planned

**Tests:** TBD

---

**Philosophy:**

LazyCSV's keybindings are currently hardcoded in `src/input/`. v0.24.1 promotes them to data — loaded from a TOML file at startup, hot-reloadable, and shippable as named preset profiles. Default behaviour stays vim-style; nothing breaks for existing users who don't opt in.

The goal isn't to support every editor's full muscle memory — it's to make LazyCSV approachable to people who don't already know vim, by letting them load a familiar preset.

---

**Features:**

**Keymap schema (`~/.config/lazycsv/keys.toml`):**
- [ ] `[normal]`, `[insert]`, `[visual]`, `[command]`, `[sql_editor]`, `[magnifier]`, `[file_menu]` sections — one per mode
- [ ] Each entry: `<key sequence> = "<action name>"` (e.g. `"j" = "cursor_down"`, `"ctrl+s" = "save"`)
- [ ] Multi-key chord support: `"gg" = "goto_first_row"`, `",dd" = "column_delete"`
- [ ] Reserved escape sequences: `"<esc>"`, `"<enter>"`, `"<tab>"`, `"<bs>"`, `"<space>"`, `"<f2>"`, `"<arrow_down>"`, etc.
- [ ] Modifier syntax: `"ctrl+x"`, `"shift+tab"`, `"alt+enter"`, `"ctrl+shift+s"`
- [ ] Setting a key to `""` (empty string) unbinds it
- [ ] Optional `[meta] inherit = "vim"` directive — load a preset, then layer user overrides on top

**Action registry:**
- [ ] Catalog every dispatchable action as a string identifier (`cursor_left`, `cell_edit`, `quit`, `enter_visual`, `paste_above`, `sql_open_history`, …)
- [ ] Single `Action` enum in `src/input/actions.rs` (already exists — extend it)
- [ ] All current dispatch tables migrated to look up actions by name
- [ ] `:keys` ex command lists every action + its current binding (sortable, searchable)
- [ ] Validation: warn on unknown actions, malformed key strings, or duplicate bindings (last wins, but report it)

**Shipped preset profiles** under `keymaps/`:
- [ ] `vim.toml` — current behaviour (default; loaded if no user file present)
- [ ] `emacs.toml` — readline-style: `Ctrl-f`/`Ctrl-b`/`Ctrl-n`/`Ctrl-p` movement, `Ctrl-a`/`Ctrl-e` line-edge, `Ctrl-x s` to save, `M-x` for command mode, no modal switching
- [ ] `excel.toml` — arrow keys for navigation, `F2`/`Enter` to edit, `Tab`/`Shift-Tab` to move horizontally and commit, `Ctrl-c`/`Ctrl-v`/`Ctrl-x`, `Ctrl-z`/`Ctrl-y`, `Ctrl-Home`/`Ctrl-End`, no modes
- [ ] `modeless.toml` — minimal binding set for users who want plain typing into cells with arrow-key navigation and no command mode

**Hot-reload:**
- [ ] `ConfigWatcher` already in place — extend it to watch `keys.toml` mtime
- [ ] On reload: rebuild the dispatch table; status bar shows "Keymap reloaded"
- [ ] Bad reload (parse error / unknown action) keeps the old table active and surfaces a warning

**Documentation:**
- [ ] `docs/keybindings.md` — restructure: cover the action catalog (the source of truth) plus per-preset cheat sheets for vim/emacs/excel
- [ ] `keymaps/README.md` — install instructions, how to author your own preset, how to inherit + override
- [ ] `docs/configuration.md` — point at `keys.toml`

---

**Implementation sketch:**

- `src/config/keys.rs` (new) — `KeymapToml`, `Keymap`, parser, action lookup
- `src/input/actions.rs` — extend `Action` enum to be the single registry; add `Action::name()` and `Action::from_name(&str)`
- `src/input/dispatch.rs` (new) — replaces hardcoded match statements in mode handlers; takes `(Mode, KeySequence) -> Option<Action>` from the active keymap
- `src/input/{normal,insert,visual,command,sql_editor,magnifier,file_list}_mode/handler.rs` — replace pattern-matched key arms with `dispatch.lookup(...)` then `Action::execute(app, …)`
- `src/config/watcher.rs` — extend to track `keys.toml` mtime alongside `config.toml`
- `src/main.rs` — load keymap at startup; fall back to baked-in `vim.toml` if missing
- `keymaps/{vim,emacs,excel,modeless}.toml` — preset files, baked into the binary via `include_str!` for the default vim profile
- `tests/keymap_test.rs` — parse-time validation, override semantics, unknown-action warning, hot-reload round-trip
- `tests/keymap_excel_test.rs` etc. — smoke-test that each preset binds the expected actions for a representative slice

---

**Compatibility & migration:**

- Default behaviour is unchanged: a user with no `keys.toml` gets the same vim-style bindings as today.
- Users who customize via `keys.toml` can pin themselves to their preset by checking it into a project-level `.lazycsv.toml` — same precedence as the theme system.
- Action names are part of the public API once shipped; renames need a deprecation window with `[meta] aliases` for old names.

---

**Open questions:**

- Should `[meta] inherit` support multiple bases (e.g. `inherit = ["vim", "macos-shortcuts"]`)? Probably yes — last layer wins.
- How do we handle bindings that don't make sense for a given mode (e.g. `"j" = "scroll_help"` in normal mode)? Either warn-and-ignore at load, or let the user shoot themselves in the foot. Lean toward warn.
- Excel-style "no modes" is a leaky abstraction — the user is still effectively in insert mode for cells. Need to think through how to surface that without the modal indicator badge feeling out of place.
