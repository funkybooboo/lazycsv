## Summary

SQL query history popup (`Ctrl+H` in SQL editor): vim-style navigation (up/down/jk), Enter to recall, `dd` to delete; persisted to `~/.config/lazycsv/sql_history` with configurable `sql_history_limit` (default 15). `SqliteCache` renamed to `DuckDbCache`; SELECT queries now use zero-cost VIEWs (column/predicate pushdown at query time) instead of materializing TABLEs; per-process spill directory lets DuckDB overflow large tables to disk instead of OOMing; DML still uses TABLEs (required for write operations); drop/cleanup correctly handles both object types. New `-o <file>` CLI flag writes query results directly to a CSV via DuckDB COPY without buffering rows in Rust. `format_number()` utility adds thousands separators to row/col counts in the status bar and query result progress messages.

## Features

- **SQL History Popup** (`Ctrl+H` in SQL editor)
  - Vim-style navigation (up/down/jk)
  - Enter to recall query, `dd` to delete entry
  - Persisted to `~/.config/lazycsv/sql_history`
  - Configurable `sql_history_limit` (default 15)

- **DuckDB VIEW Optimization**
  - SELECT queries use zero-cost VIEWs instead of materializing TABLEs
  - Column/predicate pushdown at query time
  - Per-process spill directory for large table overflow (prevents OOM)
  - DML operations still use TABLEs (required for writes)
  - Correct drop/cleanup for both VIEWs and TABLEs

- **CLI Output Flag** (`-o`)
  - `-o <file>` writes query results directly to CSV via DuckDB COPY
  - No buffering of rows in Rust

- **Number Formatting**
  - `format_number()` utility for thousands separators
  - Applied to row/col counts in status bar and query progress messages
