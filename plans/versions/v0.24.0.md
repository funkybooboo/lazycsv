- [X] Sort order indirection (sort_order vec) to avoid corrupting mmap offsets
- [X] Cursor visibility restored on TUI exit

## 1. Lazy Loading for Large Files

**Problem:** Loading 10M+ row CSV files into memory is slow and uses excessive RAM.

**Solution:** Memory-mapped file storage with on-demand row parsing.

- [X] Dual-mode `RowStorage` enum: `InMemory` (existing) and `Lazy` (mmap-backed)
- [X] Automatic threshold: files ≥10 MB use lazy path, smaller files use in-memory
- [X] Row-offset index built on load — stores byte offset of each row start
- [X] LRU cache (2048 rows) for parsed rows to avoid repeated parsing
- [X] Edit overlay: in-memory edits applied on top of lazy storage
- [X] Fast byte-level search using `memchr` + byte regex on raw mmap
- [X] Binary search on row offsets to map byte positions to row indices
- [X] Cancellable loading with Esc key support
- [X] Document API encapsulated: direct `rows` field replaced with `get_row()`, `get_rows_range()`, `row_count()`, `column_count()`

**New files:**
- `src/csv/row_storage.rs` — `RowStorage` enum, `LazyStorage` with mmap + offset index + LRU cache

**Key changes:**
- `src/csv/document.rs` — Refactored to use `RowStorage` abstraction
- `src/search/mod.rs` — Fast search path for lazy documents (byte regex on mmap)
- All test files updated to use new storage API

## 2. CLI Sort Mode

**Problem:** No way to sort a CSV from the command line without entering the TUI.

**Solution:** `--sort` / `-s` flag for non-interactive sorted output to stdout.

- [X] Sort by column name, 1-indexed number, or Excel letter (A, B, AA, ...)
- [X] Multi-column sort: `--sort "Price,Name"`
- [X] Descending sort with `!` prefix: `--sort "!Price,Name"`
- [X] Works with piped stdin: `cat data.csv | lazycsv --sort Salary`
- [X] Output as CSV to stdout for pipeline composition

**Examples:**
```
lazycsv data.csv --sort Price          # sort by Price ascending
lazycsv data.csv -s '!Price,Name'      # sort by Price desc, then Name asc
cat data.csv | lazycsv -s 2            # sort by column 2
```

## 3. Piped Stdin Support

**Problem:** Non-interactive modes didn't accept piped input, limiting Unix pipeline use.

**Solution:** All non-interactive modes read from stdin when no file path is given.

- [X] `Document::from_reader()` method for streaming CSV from any `Read` source
- [X] Query mode: `cat data.csv | lazycsv -q "SELECT * FROM stdin"`
- [X] Sort mode: `cat data.csv | lazycsv --sort Name`
- [X] Count mode: `cat data.csv | lazycsv --rows`
- [X] TUI mode: clear error message with usage examples (crossterm limitation prevents interactive stdin piping)
- [X] Temp file approach for query mode stdin (required for multi-table SQL support)

---

## 4. SQL Column Type Detection

**Problem:** All CSV columns loaded as TEXT into SQLite, causing `ORDER BY` to sort numbers lexicographically (e.g., 200 before 30).

**Solution:** Automatic column type detection with proper SQLite affinity.

- [X] Sample up to 1000 rows to classify each column as Numeric or Date
- [X] Numeric columns created with `NUMERIC` affinity in SQLite (correct numeric sorting)
- [X] Date columns detected across multiple formats: ISO, DD/MM/YYYY, MM/DD/YYYY, DD.MM.YYYY
- [X] Date values normalized to ISO format on insert for correct comparison
- [X] Locale-aware month-first vs day-first detection
- [X] Applied in all three CSV-to-SQLite loading paths: `load_csv_into_sqlite`, `load_csv_file_into_sqlite`, `load_csv_into_sqlite_cancellable`

**New files:**
- `src/query/date_detection.rs` — `ColumnType` enum, `detect_column_types()`, `normalize_to_iso()`, `sqlite_affinity()`
