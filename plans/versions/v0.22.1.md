## Outcome

LazyCSV's performance work was delivered incrementally across earlier versions
rather than as a single tuning push. This milestone closes out by acknowledging
that work and pointing to the standing benchmark suite that protects it.

### Benchmark suite

Criterion benches live under `benches/`:

- `navigation.rs` — hjkl, gg/G, page motion
- `rendering.rs` — viewport redraws across dataset sizes
- `search.rs` — `/pattern` and `:s/old/new/g` on mmap-backed and in-memory docs
- `magnifier.rs` — full-vim cell editor performance
- `sql.rs` — DuckDB query path

Run with `cargo bench`. The suite catches regressions on the critical paths
called out in the original v0.22.1 plan.

### Performance work shipped in prior versions

- **v0.24.0** — Lazy loading with memory-mapped files for large CSVs; buffered
  I/O indexing (7× faster on macOS); parallel sort with rayon; fast `memchr`
  row counting; raw-byte CSV write for sorted lazy files.
- **v0.26.0** — DuckDB-backed `SELECT` queries use zero-cost VIEWs (column /
  predicate pushdown at query time) instead of materializing TABLEs; per-process
  spill directory lets DuckDB overflow large tables to disk instead of OOMing.
- **v0.28.0** — Gzip-compressed CSV `-q` mode streams via DuckDB without
  loading the file into memory; parallel row counting with rayon for large
  files.
- **v0.29.0** — Parallelized search (`/`) for mmap-backed documents: byte-level
  regex scan split across cores, candidate rows parsed in parallel bypassing
  the LRU cache. Parallelized `:s/pattern/replacement/g` substitute with the
  same scan + parallel-replace pattern. Writer optimization for lazy storage:
  contiguous unedited byte ranges written directly from mmap in bulk; reusable
  row buffer for edited rows; 8 MB BufWriter; `sync_data()` instead of
  `sync_all()`.
