**Philosophy:**

The file browser already lets users navigate, preview, and open CSVs. v0.24.2 adds a quick escape hatch for the *other* things they want to do with files — `mv`, `rm`, `git add`, `chmod`, ad-hoc one-liners — without leaving lazycsv. Pressing `:` while the file menu is open opens a shell-command prompt. Whatever the user types is executed in the file browser's current directory.

Stdout is intentionally discarded (lazycsv is not a terminal multiplexer). Errors are not — they surface as a toast in the status bar, and optionally a scrollable popup for multi-line stderr.

Synchronous-only for v0.24.2: the TUI is suspended while the command runs. Async ("orphan") modes can come later if there's demand.

---

**Features:**

**`:` in file menu opens "Shell (block):" prompt:**
- [x] Only active when `mode == FileList` (gated by `file_list_shell_active`)
- [x] Themed centered modal at 45% width × 3 lines, borders/title/bg use `[popup]` colors
- [x] Title literal: `Shell (block):`
- [x] Single-line input with cursor block; supports `<Left>`/`<Right>`/`<Home>`/`<End>`/`<Backspace>`
- [x] `<Enter>` runs the command; `<Esc>` cancels and clears the buffer

**Variable substitution before exec:**
- [x] `$CWD` — file menu's current directory (absolute path, shell-quoted)
- [x] `$FILE` — highlighted entry's full path
- [x] `$NAME` — highlighted entry's basename
- [x] `$EXT` — highlighted entry's extension (without the dot)
- [x] Literal `$` escapable as `\$`; unknown `$<name>` tokens passthrough so the user's shell can resolve them as env vars
- [ ] `$SELECTED` deferred until multi-select on file entries lands

**Execution:**
- [x] Runs via the user's `$SHELL` (`-c "<cmd>"`); falls back to `/bin/sh` if `$SHELL` is unset
- [x] Working directory = file menu's current directory
- [x] TUI suspended via `ratatui::restore()` for the duration; aggressive `Clear(ClearType::All)` + reposition + `terminal.clear()` on resume so terminal state never leaks
- [x] Stdout discarded (`Stdio::null()`); redirections still work
- [x] Stderr captured (up to 64 KiB; truncated with `…(truncated)` marker beyond that)
- [x] Exit-code-driven outcome:
  - `0` and stderr empty → silent success; file listing auto-refreshes on next render
  - `0` and stderr non-empty → cream toast `Shell: <first line>` on the file-menu status row (full-width painted, no terminal bleed)
  - non-zero → red toast `Shell error (exit <n>): <first line>`
  - multi-line stderr → scrollable popup auto-opens with `j/k`/`d/u`/`g/G`/`Home/End`/`PgUp/PgDn` navigation; any other key dismisses
- [x] File listing auto-refreshes (existing `scan_directory_filtered` runs every render — no explicit invalidation needed)

**History:**
- [x] Persistent shell history at `~/.config/lazycsv/shell_history` (mirrors `command_history`)
- [x] Up/Down walks past entries (most-recent-first); typing or `<Backspace>` invalidates the cursor (vim-like)
- [x] Configurable `[defaults] shell_history_limit` (default 50, 0 disables)
- [x] Dedup-and-promote: re-running an existing command moves it to the front instead of duplicating
- [ ] Dedicated `:shellhistory` ex command (deferred — not strictly needed since Up/Down covers the use case)

**Implementation:**

- `src/input/file_list_mode/shell.rs` (new) — variable substitution, shell-quoting, `highlighted_entry()` helper. 3 unit tests for `shell_quote`.
- `src/input/file_list_mode/mod.rs` — `:` keypress entry point, `handle_shell_mode()` (Enter/Esc/cursor/history nav), `cancel()` updated to tear down all shell state on file-menu close
- `src/input/state.rs` — `file_list_shell_active`, `shell_buffer`, `shell_cursor` plus cursor/insert/backspace helpers
- `src/input/actions.rs` — `InputResult::RunShell { command, cwd }` variant
- `src/app/mod.rs` — `shell_history`, `shell_history_index`, `shell_history_pending`, `shell_error_popup`, plus `ShellErrorPopup` struct and the `handle_shell_error_popup_key` interceptor at the top of `handle_key`
- `src/app/file_operations.rs` — `push_shell_history()` (dedup-and-promote)
- `src/main.rs` — `handle_run_shell()` performs TUI suspend → exec → re-init with `Clear(ClearType::All)` + cursor reset + ratatui clear; populates `status_message` and (for multi-line stderr) `shell_error_popup`. Loads/saves shell history at startup/exit.
- `src/config/shell_history.rs` (new) — `load_shell_history` / `save_shell_history` mirroring `command_history`
- `src/config/{mod,toml_parsing}.rs` — `shell_history_limit` config option
- `src/ui/mod.rs` — `render_shell_prompt` (45% wide modal with cursor block + popup styling), `render_shell_error_popup` (large modal with scrollable body + dim hint line)
- `src/ui/file_manager.rs` — file-menu status bar surfaces `app.status_message` ahead of the default badges; pads to full row width so toast doesn't leak terminal bg

---

**Out of scope (deferred):**

- Async / "orphan" mode (run in background without TUI suspend)
- Interactive commands that need stdin (current path inherits stdin but the popup-on-stderr UX assumes batch usage)
- Built-in command palette / quick-actions menu — the prompt is intentionally raw shell, not a curated list
- Multi-select on file entries → `$SELECTED` substitution
- `!`/`&` flag-style prefix on the prompt (run-without-quoting / orphan-async)
