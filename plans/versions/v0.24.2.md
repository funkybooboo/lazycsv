**Tests:** TBD

---

**Philosophy:**

The file browser already lets users navigate, preview, and open CSVs. v0.24.2 adds a quick escape hatch for the *other* things they want to do with files — `mv`, `rm`, `git add`, `chmod`, ad-hoc one-liners — without leaving lazycsv. Pressing `:` while the file menu is open opens a shell-command prompt. Whatever the user types is executed in the file browser's current directory.

Stdout is intentionally discarded (lazycsv is not a terminal multiplexer). Errors are not — they surface as a toast in the status bar, and optionally a scrollable popup for multi-line stderr.

Synchronous-only for v0.24.2: the TUI is suspended while the command runs. Async ("orphan") modes can come later if there's demand.

---

**Features:**

**`:` in file menu opens "Shell (block):" prompt:**
- [ ] Only active when `mode == FileList` and the file menu is visible
- [ ] Same small-modal layout as the existing rename/delete prompts
- [ ] Themed: borders use `[popup].border_fg`, body uses `[popup].bg/fg`
- [ ] Title literal: `Shell (block):` (matches the screenshot)
- [ ] Single-line input with cursor; supports left/right/Home/End, Backspace, Ctrl-W (delete word), Ctrl-U (delete to start)
- [ ] `<Enter>` runs the command; `<Esc>` cancels

**Variable substitution before exec:**
- [ ] `$CWD` — file menu's current directory (absolute path, shell-quoted)
- [ ] `$FILE` — the highlighted entry's full path
- [ ] `$NAME` — the highlighted entry's basename
- [ ] `$EXT` — the highlighted entry's extension (without the dot)
- [ ] `$SELECTED` — newline- or space-joined list of all marked entries (deferred if multi-select isn't shipped yet)
- [ ] Substitution is positional: literal `$` can be escaped as `\$`

**Execution:**
- [ ] Runs via the user's `$SHELL` (`-c "<cmd>"`); falls back to `/bin/sh` if `$SHELL` is unset
- [ ] Working directory = file menu's current directory
- [ ] TUI is suspended for the duration: terminal is restored to normal mode, command runs with inherited tty (so the user's shell sees a real terminal), TUI is re-entered after exit
- [ ] Stdout is captured and discarded (the user's terminal won't be visually polluted, but redirection like `> out.txt` still works)
- [ ] Stderr is captured (up to 64 KiB) — never discarded
- [ ] Exit code drives the user-facing outcome:
  - `0` and stderr empty → silent success; refresh the file listing
  - `0` and stderr non-empty → status-bar toast "Shell: <first line of stderr>" with a magnifier hint
  - non-zero → red toast "Shell exited <code>: <first line of stderr>"; if stderr has more than one line, open a scrollable popup with the full text (esc to close)
- [ ] Refresh the file listing after every successful run (handles `mv`, `rm`, `touch new.csv`, etc. without needing manual reload)

**History:**
- [ ] Reuse the existing `command_history` infrastructure (or a sibling `shell_history` file at `~/.config/lazycsv/shell_history`) — Up/Down walks past entries
- [ ] `:history` ex command listing for shell commands (or `:shellhistory` if we keep them separate)
- [ ] Configurable `shell_history_limit` (default 50, 0 disables)

---

**Implementation sketch:**

- `src/input/file_list_mode/shell.rs` (new) — owns the `:` keypress capture, the input prompt state, substitution, and the exec dispatcher
- `src/ui/file_manager.rs` — render the prompt as a centered small modal when `app.shell_prompt.is_some()`
- `src/app/mod.rs` — `shell_prompt: Option<ShellPromptState>` field; `last_shell_error: Option<String>` for the popup
- `src/cancel/` — extend the existing terminal-suspend dance used for external editor invocations (if not present, factor `crossterm::terminal::disable_raw_mode + LeaveAlternateScreen` + restore into a helper)
- `src/config/{shell_history,toml_parsing}.rs` — `shell_history_limit` mirroring `command_history_limit`
- `tests/shell_command_test.rs` — substitution table-driven tests, success/silent-stderr/error/non-zero pathways via a fake `$SHELL` script, history dedup-and-promote, prompt cancel

---

**UI states:**

```
┌─Shell (block):────────────────────────────────────────────────┐
│ mv $FILE archive/                                              │
└────────────────────────────────────────────────────────────────┘
```

Status-bar outcomes (after `<Enter>`):

- silent success → status bar shows the previous "FILE MENU" mode badge again, no toast
- soft warning (exit 0 + stderr) → cream toast: `Shell: warning: foo`
- hard error (exit ≠ 0) → red toast: `Shell exited 1: rm: cannot remove 'x.csv': No such file or directory`
- multi-line stderr → red toast + a scrollable popup that opens automatically; press `:e` (errors) or just `Enter` to dismiss

---

**Out of scope for v0.24.2** (deferred, may land later):

- Async / "orphan" mode (run in background, no TUI suspend)
- Interactive commands that need stdin (use the user's terminal directly, then return)
- A built-in command palette / quick-actions menu — the prompt is intentionally raw shell, not a curated list
- Multi-select selection set ($SELECTED is wired up but only meaningful once visual-selection of file entries lands

---

**Open questions:**

- Should the prompt accept an optional flag-style prefix (`!` for run-without-quote-substitution, `&` for orphan async)? Probably yes once async lands; for v0.24.2 keep it pure.
- How do we handle commands that change `$CWD` (e.g. `cd ../other`)? The shell change won't persist back to the file menu's cwd. Document the limitation; users can navigate in lazycsv afterward.
- Should we sandbox / blocklist destructive commands? No — this is an explicit power-user feature; the warning is the `:` key-combo and the visible "Shell (block):" prompt.
